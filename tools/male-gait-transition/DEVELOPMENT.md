# Phase-locked walk/run transition trial

This is a separate review, not an engine integration. The only model input is `work/male-hand-flight/male_hands_airfoot_trial.glb`, SHA-256 `576077e068f2c48a88c208be0ad72b4214e42164d1e5b0f0f9f7050f3967e2bf`. The deliverable copies it byte-for-byte and does not add, remove, retime or edit its clips. The prior deliveries and unrelated working-tree changes are left alone. The user has not definitively approved the running foot angle.

## Runtime method

- `study-phases.mjs` evaluates 256 phases of both source cycles and searches 256 run offsets. The heuristic compares hip-relative foot, shin and hand positions, with weights 1, 0.7 and 0.25. The best combined offset is −3/32 cycle (weighted error 0.18654 versus 0.25830 at zero offset); feet alone prefer −20/256. This is an alignment heuristic, not a measurement of naturalness or a contact constraint.
- `phase-clock.mjs` keeps a common normalized walking phase; the run is sampled at that phase minus 3/32, wrapped. Walk duration is 1.041666627 s and run duration is 0.733333349 s. A critically damped weight with response 11/s moves toward 0 or 1; changing direction preserves current weight and its velocity, so it decelerates naturally rather than resetting. After 0.5 s a fresh transition has reached about 97% of its target. The phase frequency and visual ground speed interpolate with this weight; their integrals are evaluated analytically, making the clock nearly invariant to frame subdivision. At settled endpoints, an infinitesimal tail is snapped to the exact source clip.
- `locomotion-three.mjs` keeps both Three.js actions active, samples the two synced phases and blends the actual tracks. The run has no finger tracks, so Three's normal blending returns walking fingers toward their bind-pose values as the walking weight decreases. These are the original run fingers, not a new authored track. A zero-weight action remains present. This controller should own these bones; do not concurrently animate them with another mixer.
- Mixing alone can lower selected sole vertices below the floor even when each source cycle clears it. A vertical root guard measures 2,246 rest-selected sole vertices in the skinned pose against a flat world-Y floor. A C1 threshold supplies immediate clearance. `floor-envelope.mjs` adds a very small anticipatory lift to spread corrections over nearby gait phases instead of sharply lifting the root in a single frame. It is generated by `fit-floor-envelope.mjs` from 1,024 phases × 63 blend weights, circular max dilation and a 0.04-cycle raised-cosine smoothing kernel, with a 5% margin. The runtime uses the larger of this envelope and the directly measured guard. Both the envelope and the measured lift are zero in sampled settled source clips. On repeated paused sampling, the previous lift is removed before the mixer is sampled; the correction does not accumulate.
- This guard does not implement horizontal foot lock, terrain adaptation, physical collision or contact-aware inverse kinematics. The grid moves at an approximate 1.44→4.37 m/s, is integrated through the transition and may slide relative to the feet. The in-place character does not actually travel. `floorY` and the precomputed envelope are intended for this model at the original scale and a flat floor, not arbitrary actors/animations. The user's foot-angle concern remains open.

## Reproduce

```sh
npm ci --prefix tools/male-library-motion
npm ci --prefix tools/character-showcase
node tools/male-gait-transition/study-phases.mjs
node tools/male-gait-transition/fit-floor-envelope.mjs --check
node tools/male-gait-transition/build.mjs
node tools/male-gait-transition/qa-clock.mjs
# Chromium / FFmpeg paths may need CHROME_BIN and FFMPEG_BIN; large scratch
# samples belong outside the repo (choose a location with enough space).
node tools/male-gait-transition/qa-transition.mjs
node tools/male-gait-transition/qa-export-blends.mjs /tmp/bow-transition-blends.json
node tools/male-gait-transition/qa-parity.mjs /tmp/bow-transition-blends.json
python3 tools/male-rig-rebuild/qa-deform.py /tmp/bow-transition-blends.json --strict
python3 tools/male-gait-transition/qa-blend-regions.py /tmp/bow-transition-blends.json --strict-hands
node tools/male-gait-transition/record.mjs
node tools/male-gait-transition/qa-browser.mjs
python3 tools/male-gait-transition/package.py
```

The FCL checks require NumPy and python-fcl. `build.mjs --output /tmp/separate-folder` produces an independent scratch build and refuses to overwrite other repository artifacts. Package and capture scripts also accept this separate output folder. The standalone page embeds the exact model and bundled Three.js; the ZIP includes the actual three runtime modules as well as licenses. The two silent videos are captured from that page with deterministic steps, target run at 2.0 s and target walk at 5.4 s.

## Checks on this trial

- Previous model equality was checked by SHA-256. Its earlier glTF Validator run had 0 errors and 0 warnings; the same bytes remain here. The previous 4,096 off-key source samples gave minimum selected-sole heights of +2.13 mm walk and +2.24 mm run. No claim is made about the unsampled continuum.
- `qa-clock.mjs` exercised 5,000 irregular and rapidly reversed segments; the maximum single-step/subdivided clock difference was 2.22e−8. In the actual bundled viewer, 130 settled poses across both clips matched the previous viewer's bone transforms (maximum position difference 3.61e−17 m and quaternion component distance 2.81e−8); guard lift was zero.
- In 5,632 phase/weight combinations, the raw selected sole minimum was −5.53 mm; with the guard it was +1.07 mm and maximum root lift was 6.89 mm. Independent Three.js skinned-vertex checks matched the guard's floor measurement within numerical precision. Thirty-two transitions from different start phases and 128 mid-transition reversals were sampled; a switch or reversal changed neither current pose, phase, weight, weight velocity nor grid position. Repeated sampling did not accumulate a lift. At 10 ms steps the largest sampled joint displacement was 65.77 mm and rotation 9.88°, versus 60.11 mm and 8.88° in sampled steady clips; the maximum lift change was 1.79 mm. These are finite-sample proxies, not proof of perfect smoothness.
- The FCL export covers 64 off-key phases at each of four mixed weights (256 poses), 13,791 selected body vertices. Actual Three.js skinning was independently compared with 32 of those poses at 1,061 sampled vertices each; maximum coordinate difference was 0.00009 mm after subtracting the uniform guard lift. Selected knee, elbow, shoulder and hip self surfaces, hand–torso and foot–foot pairs had no non-neighbouring crossings in 256 poses; neck was checked in 64. Separate checks found no selected hand/foot self, hand–hip or same-side hand–knee crossings in those 256 blended poses. This does not erase the previously found local right walking-foot self contacts at 2/64 original walk phases, which were outside these four intermediate weights. No depth, containment, face/ear intersections, other regions or intervals between samples were measured.
- The two videos decode to 255 nonblank, distinct frames each. Offline Chromium passed emulated 320/390/768/1440 px layouts, selected body/hand/foot framing, touch-sized controls, actual clicks and reversal, phase/velocity/grid preservation, pause/seek, demo timing, reduced-motion startup, normal-speed playback, exact model download, late video seeks and WebGL fallback. HTTP/Range and package checks are also run separately. Physical phones, arbitrary gestures, engine import, terrain, translated player motion and visual quality were not verified by these automated tests.

An art review of the motion and foot angle at normal speed is still needed; no finite geometric sample establishes that they look natural.

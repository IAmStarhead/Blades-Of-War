# Отдельная проба хвата и ушей модели А

[Результат, сравнения и инструкция для просмотра](../../work/character-model-search/selected-a/hand-ear-study/) — отдельный вариант предыдущей [пробы моргания и кистей](../../work/character-model-search/selected-a/motion-study/). Её GLB и ZIP не перезаписываются. Волосы, лицо, материалы, текстуры, освещение и колодец не меняются.

## Устройство модели

- Входной `female_A_motion.glb` проверяется по SHA-256 `713cb5004612bb3c4707406ec863147a17a6b23e68e192e99177f5b469b313f7`. Позиции, нормали и UV нейтральной модели вне окрестности ушей не изменены. Тело, глаза, линии век, изображение кожи и моргание унаследованы из него. В открытом положении обе кисти идентичны прежним.
- `ears.py` применяет два умеренных сглаживающих прохода с затуханием к границам ушей, затем разделяет только внутренние рёбра локального изменённого участка. На UV-швах сохраняются раздельные UV-вершины с совпадающими геометрическими координатами. Смещены 762 исходные вершины, максимум на **1,91 мм**; добавлено 2 310 вершин и 4 620 треугольников ушей. После геометрической сварки швов у каждого ребра по две смежные грани; нулевых и перевёрнутых граней не обнаружено. Старые грани за пределами выбранного участка сохранены. На основе тела/лица 15 866 → 18 176 вершин; общий счётчик всех мешей 31 066 → **35 686 треугольников**.
- `hands.py` подгоняет каждый палец и большой палец, зеркалируя оси и точки вращения для обеих рук. Временные веса и суставы берутся из вспомогательного `work/character-showcase/prototype/assets/models/female_fixed.glb` с SHA-256 `bbde88441ee4f32f640e5a5a0d81b06989328ee5afede2732c42c4e5ef8ff158`. Совпадение порядка UV первых 14 517 вершин проверяет прежний сборщик; поза запекается именно на геометрию А. Скелет в итоговый GLB **не переносится**.
- `Fists` хранит конечную позу, а `FistQuarterCorrection`, `FistHalfCorrection`, `FistThreeQuarterCorrection` — поправки промежуточных форм и нормалей. Веса для управления ползунком приведены в пользовательском README. Ключевые формы соответствуют 0%, 25%, 50%, 75%, 100%; промежуточный путь включает небольшое временное разведение пальцев и продвижение больших пальцев. Линейная интерполяция вершин между корректирующими формами не является суставной анимацией.
- У `Fists_Close` и `Fists_Open` по девять ключей в течение 0,35 с; четверти явно включены, поэтому клипы следуют тому же кусочно-линейному пути, что и ползунок. `Blink_Once` и морфы лица/век не изменены; движение кистей и моргание воздействуют на разные узлы и могут проигрываться одновременно. Все нейтральные веса равны нулю. Сами клипы однократные; удержание конечной позы или автоматическое повторение зависят от движка или кода витрины.
- Витрина включает отдельные ракурсы ушей и ползунок, но использует прежние текстуры, свет и bundle процедурного колодца из проверенного исходного ZIP. Отдельного GLB колодца нет. В GLB больше геометрии и морф-атрибутов; GPU-память и фактическая производительность зависят от импортёра, замеры FPS не выполнялись.

## Сборка и проверки

Требуются Python 3.11, Node.js и исходные материалы по путям из `build.py`. После установки зависимостей сборка не обращается к сети. `python-fcl` необходим геометрической проверке, но не сборщику. В некоторых системах Chromium дополнительно требует системные библиотеки; можно задать `CHROME_BIN`.

```bash
python3 -m venv /tmp/bow-hand-ear-venv
. /tmp/bow-hand-ear-venv/bin/activate
pip install -r tools/model-a-hand-ear/requirements.txt
python tools/model-a-hand-ear/build.py
python tools/model-a-hand-ear/qa.py
python tools/model-a-hand-ear/qa-geometry.py --samples 201
npm ci --prefix tools/character-showcase
npm ci --prefix tools/model-a-motion
node tools/model-a-hand-ear/qa-gltf.mjs
PYTHON=python node tools/model-a-hand-ear/qa-browser.mjs
# Переснять реальные сравнения с одинаковой камерой:
PYTHON=python node tools/model-a-hand-ear/qa-browser.mjs --shots
```

Сборщик принимает `--source`, `--rig`, `--well-archive`, `--output`; структурный тест — `--source`, `--result`, `--well-archive`; геометрический — `--result`, `--rig`, `--samples`. Браузерный и glTF-тесты принимают позиционный путь к результату. На программном WebGL браузерный тест может занимать несколько минут. `review.py` только обрезает готовые снимки и добавляет подписи; ладонные виды изолируют выбранную кисть **только при рендере**, не изменяя поставляемую модель.

### Результаты проверок

- `qa.py` проверяет локальность исходных позиций и нормалей, неизменность UV вне добавленных вершин, текстур, материалов, лица, открытых рук, морфов моргания и узлов, замкнутость сваренной сетки и ориентацию граней; отдельно проверяет локальность/швы четырёх морфов, веса клипов, независимость моргания и содержимое ZIP.
- Khronos glTF Validator: **0 ошибок, 0 предупреждений, 0 информационных сообщений** как у исходного, так и у нового GLB.
- Браузерный тест открыл обе автономные витрины без внешних запросов, проверил клипы через настоящий `AnimationMixer`, ползунок и флажок, независимое моргание, ракурсы, мышь и сенсорное управление, экраны 390×844 и 320×568, а также `prefers-reduced-motion`. При одинаковых камерах открытые руки и центральная часть лица, возврат из поз и колодец в двух режимах совпали попиксельно с соответствующими проверочными снимками. Снимки ушей отличаются на обеих сторонах.
- `qa-geometry.py` использует python-fcl на **201 дискретном весе** 0…1 для обеих рук. В каждой руке проверены 3 247 выбранных по весам рига треугольников с исключением пар, имеющих общую сваренную вершину; дополнительно проверены пары с 1 170/1 171 выбранными треугольниками ноги соответствующей стороны. Новых пар самопересечений кисти и пересечений с выбранной ногой на этих отсчётах не выявлено. Это не проверка всех граней, противоположной ноги или непрерывного времени.
- В **неизменённой исходной открытой позе** есть по пять непринадлежащих общему ребру/вершине контактирующих пар на каждой кисти у основания большого пальца. Они исключены из счёта *новых* контактов, но отслеживаются отдельно: в последних выполненных отсчётах они встречались до веса **0,095**, при 0,100 их уже не было. Их геометрия во время движения может изменяться, поэтому результат не означает отсутствия самопересечений. На 201 отсчёте максимальный рост сообщённой FCL глубины был 2,892 → 3,878 мм при весе 0,015 для левой пары групповых треугольников `(2886, 3028)`; при этом непосредственно вычисленная длина линии пересечения этой пары уменьшилась с 0,760 до 0,319 мм. Для другой исходной пары `(2758, 3012)` максимальная измеренная длина линии увеличилась с 0,685 до 0,783 мм при весе 0,045. Эти две величины не равнозначны глубине объёмного проникновения; ни одна не является доказательством безопасности всей сетки. Исходную открытую кисть намеренно не исправляли, чтобы не изменить прежнюю форму.

- GLB: **3 890 488 байт**, SHA-256 `443a06634ec5d6d8dcee27f956022b511fc7012b4c3323e1320f15ec90d74707`.
- ZIP: **3 504 818 байт**, SHA-256 `db01f1dec38115572ac14c5c8d7adb0eb7950571f1a735d2b4997b14779625d8`.

# Blades Of War

Текстовая симуляционная песочница на **Twine 2 / SugarCube 2**, собираемая в один
самодостаточный HTML-файл. Работает в обычном браузере без сервера и без интернета.

**Текущая версия: 0.0.5 «Тихие руки»** — играбельный прототип.
Интерфейс: логотип-кнопка, выдвижная панель, рельса значков, диалог-лента с репликами героя,
холодный камень вместо тёплых подложек, липкая шапка и складывающиеся блоки на телефоне.
Новое: работа за деньги (навык решает исход), рост навыков, отношение общин к игроку
и цены, которые от него зависят.

---

## Быстрый старт

### Играть без сборки
Откройте `dist/BladesOfWar.html` двойным щелчком. Всё, включая движок, стили и
логику, находится внутри этого файла.

### Собрать самому
```bash
npm install
npm run build      # .twee → dist/BladesOfWar.html
npm run check      # 95 автоматических проверок логики и разметки
npm run verify     # сборка + проверки одной командой
```

Требуется Node.js 18+. Сборщик — `extwee` (npm). Формат истории SugarCube 2.37.3
лежит в `vendor/format.js`, поэтому сборка не требует интернета.

## Что НЕ реализовано

Обозначено честно, чтобы не выглядело готовым:

- армии, сражения, осады;
- династии, браки, наследование;
- строительство и производство;
- фракции с самостоятельными решениями (сейчас есть только описания организаций и репутация персонажей);
- инквизиция, изгои, каннибалы, рабство, законы регионов;
- слухи как полноценная система распространения (есть только отдельные записи в журнале);
- механическое влияние погоды на урожай, дороги и торговлю;
- болезни, травмы, сезоны влияющие на экономику;
- второй играбельный регион;
- карта местности.

Подробный план: `docs/DESIGN.md`.

## Структура проекта

```
src/
  js/            игровая логика, по модулям
    000-core      утилиты, ГПСЧ, шина событий
    005-data      ВСЕ игровые данные (правится без кода)
    010-state     создание, проверка, миграции состояния
    020-time      календарь и тики
    030-needs     потребности и здоровье
    040-economy   деньги, предметы, торговля
    050-journal   журнал и события
    060-actions   действия игрока
    070-events    причинные происшествия
    080-save      сохранения, контрольная сумма
    100-adapter   стык ядра с SugarCube
    110-ui        отрисовка интерфейса
    900-game      обработчики кнопок, автосейв, файлы
  ui/
    010-interface разметка экрана (StoryInterface)
    200-widgets   виджеты (торговля)
    900-styles    всё оформление
  passages/       мета-пассажи и стартовый пассаж
tools/
  build.sh        склейка + сборка + проверки
  check.js        35 автотестов в эмуляции браузера
vendor/format.js  формат SugarCube 2.37.3 (нужен для сборки)
dist/BladesOfWar.html  готовый файл для игры
```

**Главный архитектурный принцип:** модули `000`–`080` не знают ни про SugarCube,
ни про DOM. Они получают состояние и возвращают результат. Стыковка — только в
`100-adapter`. Поэтому ядро можно перенести в другой движок, не переписывая логику.

## Как менять игру

### Названия, персонажи, цены, описания локаций
Всё в одном файле: `src/js/005-data.twee`. Меняете текст — пересобираете — играете.
Кода касаться не нужно. Там же помечено, что поселение **Студёный Брод** — тестовое
и подлежит согласованию.

### Баланс
`needsRules` в том же файле: скорость голода, пороги, сколько даёт отдых.

### Внешний вид
`src/ui/900-styles.twee`. Палитра задана переменными в `:root` в начале файла.
Логотип встроен в CSS как data URI (переменная `--bow-logo`), поэтому готовый
HTML остаётся одним файлом без внешних ссылок. Исходники логотипа — в `assets/`.

### Логику
Модули в `src/js/`, каждый отвечает за своё. Новую систему добавляйте отдельным
файлом с префиксом по порядку (`065-...`), подписывайтесь на шину событий
`Bow.bus.on("tick:hour", ...)` вместо правки существующих модулей.

## Работа в Twine 2

Проект собирается из `.twee`, поэтому в Twine 2 его можно открыть так:

1. Соберите HTML: `npm run build`.
2. В Twine 2: **Библиотека → Импорт → выберите `dist/BladesOfWar.html`**.
3. История откроется со всеми пассажами. Пассажи с метками `script`, `stylesheet`
   и `widget` останутся на своих местах.

Обратно в проект правки переносятся вручную: Twine не умеет экспортировать в
несколько `.twee`-файлов. Если работаете в Twine — держите изменения в одном
файле и переносите в `src/` осознанно.

Cкрипты в Twine выполняются в том же порядке, что задан именами файлов.

## Проверки и их границы

`npm run check` прогоняет 95 проверок: запуск движка, отрисовку панелей, время,
торговлю, потребности, разговоры, сохранения (включая битые и подделанные),
события, наличие медиазапросов и отсутствие внешних ссылок.

**Чего эти проверки не делают:** не смотрят на игру глазами. Chromium в песочнице
разработки недоступен, поэтому визуальная приёмка и поведение на реальном телефоне —
за владельцем проекта.

# Blades of War — ходьба и бег в гору

Это отдельная проба подъёма на плавный склон. Персонаж движется от ровной поверхности к вершине; стопы и колени подстраиваются под наклон. Одобренный переход ходьба ↔ бег сохранён и работает на склоне. Предыдущие файлы не заменены.

## Как посмотреть

1. Распакуйте ZIP и откройте **`index.html`** в браузере с поддержкой WebGL. Для 3D-просмотра интернет не нужен. Начнётся ходьба на склоне 15°; если в системе включено уменьшение движения, показ начнётся на паузе — нажмите «Пуск».
2. Выберите **«Ходьба»** или **«Бег»** под моделью, в том числе посреди подъёма. Фаза шага и положение персонажа при переключении не сбрасываются. Повторное нажатие другой кнопки во время перехода плавно меняет его направление. По достижении верхней площадки нажмите «Ещё раз» или «Повторить подъём».
3. Кнопки **0°, 10°, 15°, 20°** меняют наклон и начинают маршрут снизу заново. 0° — ровная земля. «Весь склон» показывает маршрут; остальные ракурсы следуют за персонажем. Для осмотра контакта выберите «Обе стопы» и «Сбоку».
4. Ползунок фазы ставит движение на паузу; нажмите «Пуск», чтобы продолжить. «Скорость ½» замедляет движение и переход. Перетаскивайте мышью или пальцем для вращения; колесо или два пальца меняют масштаб. Кнопка скелета показывает суставы.
5. Если 3D не работает, откройте видео без звука: `uphill_walk.mp4`, `uphill_run.mp4`, `uphill_transition.mp4` или `uphill_feet.mp4`. Бег показан сначала на обычной скорости, затем повторяется в замедлении; остальные ролики идут на обычной скорости.

## Что входит в модель, а что — в код

**Подъём и переход не записаны в GLB как новые клипы.** `male_hands_airfoot_trial.glb` — побайтово прежняя модель с исходными клипами ходьбы и бега. Если открыть только GLB в другой программе, подъёма там не будет. Его создаёт код просмотрщика: передвижение по высоте поверхности, поворот стоп, двухсуставная подстройка ног, небольшие поправки таза и корпуса. На ровной поверхности используется тот же фазовый переход, что и в предыдущей пробе.

В архив положены `uphill-controller.mjs`, `terrain.mjs`, `phase-clock.mjs`, `floor-envelope.mjs` и `locomotion-three.mjs`: это тот же код, что встроен в страницу. Простейший пример для Three.js и исходной модели:

```js
import {Group} from 'three';
import {RampTerrain} from './terrain.mjs';
import {UphillController} from './uphill-controller.mjs';

// gltf — загруженный male_hands_airfoot_trial.glb; scene — ваша сцена.
const actor = new Group();
actor.add(gltf.scene);
scene.add(actor);
const terrain = new RampTerrain(15);
const uphill = new UphillController(actor, gltf.scene, gltf.animations, terrain);
uphill.reset('walk', 0, -2.7); // состояние, фаза, положение по Z
// В обновлении кадра:
uphill.step(deltaSeconds);
// В любой момент:
uphill.setTarget('run');       // или 'walk'
```

Это **не готовая интеграция в игровой движок**. Контроллер рассчитан на этот именованный риг в исходном масштабе, Y вверх, движение строго по +Z и одинаково ориентированные единичные transforms модели, группы `actor` и её предков. Он управляет теми же костями, что и микшер, поэтому другой микшер не должен управлять ими одновременно. Пример поверхности — только гладкий прямой подъём с ровными площадками; он ограничен 0–20°. Для другого движка, направления или рельефа нужна отдельная адаптация и проверка.

## Ограничения

Горизонтальная фиксация опорной стопы не реализована — возможно скольжение. Для доступности цели ноги на склоне шаг может укорачиваться. Лестницы, обрывы, спуск, повороты, столкновения и физика не реализованы. Выборочные геометрические проверки не гарантируют отсутствия пересечений во всех фазах и не заменяют визуальную оценку. В исходной ходьбе ранее обнаружены локальные пересечения треугольников правой стопы; при выборке подъёма они тоже встречались. В двух пробных позах вычисление в мировых координатах также показало единичные контакты шеи, исчезавшие при переносе начала координат перед проверкой. Глубина и заметность этих контактов не измерялись. Оцените, пожалуйста, движение и угол стопы на обычной скорости.

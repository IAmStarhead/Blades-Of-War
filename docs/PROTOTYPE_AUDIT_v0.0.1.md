## 3. Подтверждённые дефекты

### 3.1. Стартовые события и журнал не появляются (критично)
`data.js` вызывает `GameEngine.getState()` — а метод возвращает **глубокую копию**
состояния (`JSON.parse(JSON.stringify(state))`). Записи уходят в копию.

Прогон: после `initGameData()` → `events: 0`, `journal: 0` (ожидалось 2 и 1).

### 3.2. Кнопка «Отдохнуть» не работает (критично)
В разметке: `onclick="app.goTo('tavern_rest')"`. Локации `tavern_rest` нет.

Прогон: `move("tavern_rest")` → `{"success":false,"message":"Место неизвестно."}`.
Рабочий метод `app.rest()` существует, но ни к одной кнопке не привязан.

### 3.3. Время идёт вдвое быстрее (критично)
`moveTo()` делает `state.time.hour += 1`, затем вызывает `advanceTime(1)`, который
прибавляет ещё час. `rest()` — то же самое с четырьмя часами.

Прогон: старт 8:00 → один переход → **10:00** (ожидалось 9:00).
Отдых: 10:00 → **18:00** (ожидалось 14:00).

### 3.4. Потребности падают от числа вызовов, а не от времени
`updateNeeds()` не принимает длительность. Час прошёл или восемь — падение одинаковое.
Нижние границы нарушены: прогон 60 циклов → `health: -2`, `mood: -5`.
Верхние границы есть (`Math.min(100, …)`), нижние — частично отсутствуют.

### 3.5. Пол персонажа игнорируется (заметно)
Текст разговора жёстко женский: «**Она** кажется осторожной», «**Она** помнит ваш
прошлый разговор». Для Горна (мужчина, бывший солдат) это фактическая ошибка.

### 3.6. Валидация сохранений отсутствует (опасно для прогресса)
- Полувалидный JSON `{"version":"0.0.1","data":{"player":{}}}` принимается (`true`),
  после чего `getPlayer()` падает: `state.player.inventory is not iterable`.
- При несовпадении версии — только `console.warn`, загрузка всё равно выполняется.
- Миграций нет. Битый JSON отклоняется корректно (`false`) — единственный корректный путь.

### 3.7. Двойной учёт денег
В инвентаре лежит `item_coin` с `qty: 15` **и** отдельное поле `player.money: 15`.
Продажа предметов не синхронизирует эти сущности.

### 3.8. Мелочи
- При покупке двух хлебов в инвентаре появляются три записи с `id: "item_bread"` —
  стекирования и уникальных id нет.
- `events.log` и `journal` растут без ограничений (прогон 50 вызовов → 50 записей).
- Сохранение только в файл: закрыл вкладку — прогресса нет.
- README ссылается на `backups/v0.0.1-before-redesign/`, которой в архиве нет.
- README заявляет «три поселения» и «четыре локации» вперемешку; фактически 4 локации
  внутри одного поселения.
- README описывает импорт в Twine как возможный «если Twine поддерживает» — это не так.

## 5. Вывод

Прототип полезен как источник идей интерфейса и структуры состояния, но как фундамент
не годится: несколько ключевых действий не работают, время и потребности считаются
неверно, сохранения могут испортить прогресс.

**Решение:** не переносить код в новый проект. Перенести *идеи* (панели, набор
потребностей, структура памяти) и реализовать их заново на чистом ядре SugarCube 2.
Старый архив остаётся в репозитории как история версии.

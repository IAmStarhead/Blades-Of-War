# Three-pass ear repair review

Left: `ear-front-surface-trial` (46d9276). Right: three stages: (1) inspect boundary loops to identify the front-surface opening responsible for seeing the pale rear face; (2) fill this small closed boundary with triangles using its existing vertices, both ears for both figures; (3) taper upper-root tip vertices slightly and inspect front, profiles, three-quarter, alternate light and static head turn/tilt. The observed ear boundary loops have six vertices on one side, eight on the other; runtime diagnostics confirmed 4 and 6 new triangles respectively for both characters. The accepted female lobe and face are not intentionally changed. The existing static back-surface tint is still present, so appearance is not solely a consequence of new geometry.

The visible horizontal break is reduced, but patch shading remains, as do upper sharp points/gaps, rear fragments and a separate intersecting ear/head junction. The added triangles close a particular loop in the ear mesh; they do not weld ear to head or create an anatomical canal. The head poses shown are static, not a full animation test. Do not integrate without review.

Compare with Vite at `/src/ear-three-pass-trial/`; PNGs are in `docs/previews/ear-three-pass-trial/`. `node tests/ear-three-pass-trial.mjs` checks synthetic 6/8 vertex boundaries, triangulation once, unchanged positions at patching, indices during root smoothing, and finite normals; browser checked actual patch counts and screenshots. `npm run verify` checks project logic, not visual quality.
